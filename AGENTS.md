# Fork scope

- This is the user's Codex fork, bundled by the Flutter desktop client in `../client/`. Keep the upstream Rust agent loop, app-server protocol, authentication, prompts, configuration, compaction, goals, subagents, MCP and tool behavior. Port upstream updates with small, reviewable changes.
- Preserve upstream application HTTP behavior: endpoints, methods, headers, routing, authentication, payloads, streaming, retries and cancellation. Do not invent identities or change model/authentication requests to accommodate packaging. Build and package with an explicit nonzero release version and the actual source commit; `0.0.0` must never reach model requests. Protocol parity cannot guarantee an account outcome.
- The intentional architecture change is process topology: execute code-mode JavaScript in-process through `rquickjs`. Preserve session isolation, persistent bindings, async tools, outputs, cancellation, deadlines and cleanup. Do not bundle Node or spawn a code-mode host for local execution. Explicit remote code-mode endpoints retain their ownership.
- Agent-requested shell/command tools and shell environment snapshots may spawn subprocesses. Inspect other process launches before changing them; do not replace necessary command execution with a stub.
- Configured local stdio MCP servers share one subprocess per declaring config file and server name within this Codex backend process. Global declarations are shared across projects; each project declaration has its own owner. Preserve per-conversation policy, callback routing and cancellation. Keep plugin and remote-executor transport ownership unchanged. Excluding Node from our own bundle does not prohibit a configured external MCP server.
- Read the current source and its callers before editing. Distinguish implemented behavior from gaps; do not silently fall back to another engine or claim unverified parity.
- Plan mode is deferred. Do not expand this milestone into unrelated UI or plan work.
- Do not format or write/run tests unless explicitly requested by the user. Use focused compilation checks for Rust changes; coordinate builds so agents do not compete for the same build directory. Never submit a model request solely as a probe.
- Preserve unrelated concurrent work. Assign agents nonoverlapping files and coordinate shared public APIs before integrating.
- Use the repository's `kache` Cargo compiler wrapper for Rust builds. Install `kache` on the build host; do not change global Cargo or shell configuration. It is build tooling and is never bundled into the runtime application.
